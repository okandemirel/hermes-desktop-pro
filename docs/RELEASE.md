# Hermes Desktop Pro Release Flow

Hermes Desktop Pro uses `electron-updater` with GitHub Releases. The in-app update
button does not read `main`, npm, or a local build. It checks the public GitHub
release feed generated by `electron-builder`.

## Update Button Requirements

The in-app update button can install an update only when all of these conditions
are true:

- Hermes is running as a packaged app. Development mode and `electron-vite
  preview` report updates as unsupported.
- The installed app version is lower than the newest published GitHub Release.
- `package.json` has been bumped to that newer version before publishing.
- The release exists in `okandemirel/hermes-desktop-pro`, which is the feed
  configured in `src/main/app-updater.ts`.
- The release contains the generated updater assets: `latest-mac.yml`, macOS
  `.dmg`, macOS `.zip`, and `.blockmap` files.
- Public macOS artifacts are signed with Developer ID Application and notarized.
- The user can reach GitHub Releases from the installed app.

There is no npm upload requirement. The updater source for this app is GitHub
Releases.

## Required GitHub Secrets

Public macOS updates must be signed and notarized. Configure these repository
secrets before publishing a release:

- `CSC_LINK`: base64-encoded Developer ID Application certificate, or a secure URL
  to the certificate file supported by electron-builder.
- `CSC_KEY_PASSWORD`: certificate password.
- `APPLE_API_KEY`: App Store Connect API key contents.
- `APPLE_API_KEY_ID`: App Store Connect API key id.
- `APPLE_API_ISSUER`: App Store Connect issuer id.

## Publish A New Update

1. Bump `package.json` version to a value higher than the currently installed app.
2. Commit the version bump and release changes.
3. Create and push a matching tag:

```bash
git tag v2.0.1
git push origin main
git push origin v2.0.1
```

4. GitHub Actions runs `.github/workflows/release.yml`.
5. The workflow publishes macOS `.dmg`, `.zip`, blockmap, and `latest-mac.yml`
   assets to GitHub Releases.
6. Installed Hermes apps check that feed and can download/install the update.

## Why The Button Can Turn Active Without Installing

The button can enter an active/checking state while Hermes asks GitHub whether a
new release exists. Installation is only possible after the updater downloads a
release asset and enters the `downloaded` state. If there is no GitHub Release, no
`latest-mac.yml`, or no newer version number, there is nothing to install.

## What Does Not Trigger An Update

These actions do not create an installable update by themselves:

- Pushing commits to `main` without publishing a newer GitHub Release.
- Running `npm install` or uploading anything to npm.
- Building a local `.app` without publishing release metadata.
- Publishing a release with the same or lower version than the installed app.
- Publishing release assets without `latest-mac.yml`.
- Shipping unsigned or unnotarized artifacts to public users.
